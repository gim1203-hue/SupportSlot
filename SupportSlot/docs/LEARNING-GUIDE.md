# Learn the project in order

1. Read client/src/main.jsx. React mounts App in the root HTML element; CSS supplies the visual presentation.
2. Read client/src/App.jsx. useState stores session, selected service, and page. useEffect loads server data once. Conditional JSX selects the screen. The service filter uses Array.filter and cards use Array.map with database IDs as stable keys.
3. Read components/ServiceCard.jsx. Props carry a service record down; the onSelect callback carries a user action up. It does not fetch or change the database.
4. Read api.js and AuthForm.jsx. fetch sends HTTP requests. FormData reads inputs. Errors become visible messages. The browser receives a session cookie automatically; JavaScript cannot read the HttpOnly token.
5. Read server/src/routes/auth.js and middleware/auth.js. Registration hashes passwords. Login verifies the hash. Authentication verifies a signed token and loads the current database user. Authorization checks the role separately. Client-supplied roles are discarded.
6. Read server/src/models.js. Mongoose schemas describe stored documents. References connect bookings to users and services. The database unique index is what resolves simultaneous reservations reliably.
7. Read services/scheduling.js and BookingForm.jsx. Availability is generated by the server. The form effect ignores stale responses after the date changes. The server validates the selected time again when reserving.
8. Read routes/bookings.js. The ownership filter prevents one user from changing another user's appointment. Cancellation and completion use conditional atomic updates.
9. Read services/recommendation.js and Assistant.jsx. AI output is untrusted: parse JSON, validate fields, check the catalog ID, then display it for review. Fallback is labeled accurately. Your booking route remains independent of model output.
10. Read test/integration.test.js. The concurrency test submits competing requests and asserts exactly one succeeds. Other tests check permissions, invalid times, cancellation, and provider output validation.

After each section, explain it aloud and change one small thing yourself. Example practice tasks: add an empty catalog message; improve password validation feedback; add an admin queue filter; write an evaluation case for ambiguous issues. Keep your real changes in separate meaningful commits.
